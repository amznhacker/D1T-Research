# D1 Arm JSON Command Protocol

Cleaned-up reference for the JSON protocol carried inside DDS `ArmString_` messages.
Source: [Unitree D1 Arm developer docs](https://support.unitree.com/home/en/developer/D1Arm_services).

## Message envelope

Every message — command or feedback — is a JSON string with four top-level fields:

```json
{"seq": 4, "address": 1, "funcode": 1, "data": { ... }}
```

| Field | Meaning |
|---|---|
| `seq` | Sequence number identifying this message. |
| `address` | Which subsystem the message is for/from (see below). |
| `funcode` | The specific instruction within that subsystem. |
| `data` | Instruction payload — itself a JSON object, shape depends on `funcode`. |

### `seq` rules

- For commands **you send**, `seq` is generated by your own code — it's just a tag you pick (the example programs all use `4`).
- For **feedback/status messages** coming from the arm, `seq` is fixed at `10`.
- Replies don't re-parse or echo content — they simply echo back the `seq` of the command they're responding to, so you can match a reply to the request that caused it.

### `address` namespace

| address | Direction | Purpose |
|---|---|---|
| `1` | Host → arm | Commands (move joints, enable/disable, power, zero) |
| `2` | Arm → host | Continuous state feedback (angles, status, motor health) |
| `3` | Arm → host | Per-command acknowledgement (received OK? executed OK?) |

---

## Commands (`address: 1`)

Sent by you, to the arm. `seq` is whatever you choose.

| funcode | Function | `data` fields | Notes |
|---|---|---|---|
| `1` | Single joint angle control | `id`, `angle`, `delay_ms` | `id` = joint number, `angle` = target angle, `delay_ms` currently unused (set to `0`) |
| `2` | All joint angle control | `mode`, `angle0`…`angle6` | `mode 0` = smoothed 10 Hz streaming updates; `mode 1` = trajectory-style large smoothing |
| `4` | Single joint enable / de-energize | `id`, `mode` | `mode 0` = de-energize (free the joint), `mode 1` = enable |
| `5` | All joints enable / de-energize | `mode` | Same `mode` semantics as funcode `4`, applied to every joint |
| `6` | Arm motor power switch | `power` | `power 0` = power off, `power 1` = power on |
| `7` | Return to zero posture | *(none)* | No `data` field at all |

**Examples:**
```json
{"seq":4,"address":1,"funcode":1,"data":{"id":5,"angle":60,"delay_ms":0}}
{"seq":4,"address":1,"funcode":2,"data":{"mode":1,"angle0":0,"angle1":-60,"angle2":60,"angle3":0,"angle4":30,"angle5":0,"angle6":0}}
{"seq":4,"address":1,"funcode":5,"data":{"mode":0}}
{"seq":4,"address":1,"funcode":7}
```

## State feedback (`address: 2`)

Pushed continuously by the arm. `seq` is always `10`.

| funcode | Function | `data` fields | Notes |
|---|---|---|---|
| `1` | Joint angle feedback | `angle0`…`angle6` | Real-time joint angles, pushed at 10 Hz |
| `3` | Arm status feedback | `enable_status`, `power_status`, `error_status` | Each is `1` = OK/enabled/powered, `0` = disabled/off/faulted |
| `4` | Motor online status | `motor0_status`…`motor6_status` | `1` = motor healthy, `0` = motor fault |

**Example:**
```json
{"seq":10,"address":2,"funcode":1,"data":{"angle0":0,"angle1":-60,"angle2":60,"angle3":0,"angle4":30,"angle5":0,"angle6":0}}
```

---

## Command acknowledgement (`address: 3`)

Sent back by the arm in direct response to a command you sent on `address: 1`. `seq` echoes the original command's `seq`.

| funcode | Function | `data` fields | Notes |
|---|---|---|---|
| `1` | Receipt acknowledgement | `recv_status` | `1` = message received and parsed OK; `0` = malformed, unparsable, or out-of-range command |
| `2` | Execution acknowledgement | `exec_status` | `1` = command executed successfully; `0` = execution failed |
